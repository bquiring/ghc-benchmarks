# webs-hackage-bench

Benchmarks for the GHC web transformations (`ghc-webs`, branch `webs`) on real
Hackage programs, kept apart from nofib and from the GHC repository.

Each benchmark is a Hackage executable run on a fixed input:

| benchmark   | program                    | input                                              |
|-------------|----------------------------|----------------------------------------------------|
| happy       | happy 2.1.3                | GHC's parser grammar, `compiler/GHC/Parser.y`      |
| alex        | alex 3.5.2.0               | GHC's lexer, `compiler/GHC/Parser/Lexer.x`         |
| cpphs       | cpphs 1.20.10              | GHC's `compiler/GHC/*/*.hs`, concatenated          |
| skylighting | skylighting 0.13 (CLI)     | `compiler/GHC/Core/Opt/Simplify/Iteration.hs` (HTML on stdout) |

(`benchmarks.txt` lists them; pandoc 2.19.2 is set aside: its cached
dependencies do not build with GHC 9.15.)

## Use

```
./setup.sh                       # unpack from the local cabal cache, pin versions, make inputs
./build.sh base ""               # one configuration: NAME "EXTRA GHC OPTIONS"
./build.sh ulsl "-fcore-webs-early ... -dcore-lint"
python3 time.py base ulsl        # pinned, interleaved rounds; results/timing-<label>.md
```

Every package, the benchmarks and all their dependencies except the
compiler's boot packages (as in nofib), is built with `-O2` and the
configuration's options (`NAME.project`, generated by `build.sh`), into
`store/` and `dist-NAME/`.  `time.py` counts user-space instructions
(perf), allocation and mutator/GC time (`+RTS -t`), checks that every
configuration produces the same output, and reports each configuration
against the first.

## Notes

* The compiler is the GHC tree's stage-2 compiler: `GHC_TREE` (default
  `~/projects/ghc-webs`); `cabal.project`'s `with-compiler` is a literal
  path and must match.
* Everything comes from the local cabal cache (`~/.cabal/packages`), with no
  network: `gen-constraints.py` pins every cached package to its newest
  cached version (`cached.project`), because the solver otherwise picks
  uncached versions.  `cabal --offline` is not used: it refuses even cached
  dependencies.
* GHC 9.15 is newer than most packages allow (`allow-newer: all`), and
  ships Cabal 3.15, which cabal-install 3.12 will not use for custom
  `Setup.hs` scripts; `fix-custom-setups.py` switches the dependencies whose
  custom setup exists only for doctests to `build-type: Simple`.
* Builds run under the machine's resource limits (`ulimit -v`, and a
  `systemd-run` scope when called from the GHC tree's scripts).
